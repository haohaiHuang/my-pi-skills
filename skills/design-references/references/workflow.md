# 环节操作手册 — 五环节动作序列 × 资源调用 × 退化链

> 配合 SKILL.md 路由使用。每环节：目标 → 动作序列 → 资源调用（主→次→兜底）→ 产物格式 → 退化链。
> 铁律：参考必须转译成约束（环节 2），不"看一眼"就产出；信息不全先问询（≤3 问）。

---

## 环节 0 · 意图澄清 → Brief

**目标**：把一句话需求变成可执行的四要素 Brief。

**动作序列**：

1. 识别场景分支（A/B/C）
2. 按分支问询缺口（见 SKILL.md 问询协议），已推断的跳过
3. 输出 Brief：格式 / 渠道 / 受众 / 目标 / 硬约束

**产物格式**：

```
场景: A1 APP | 格式: 移动端 UI | 受众: 泛 C 端 | 目标: 转化 | 硬约束: 品牌色已定/双端
```

**资源调用**：无（约束输入）。

**退化链**：无（问询本身就是最轻动作；拒绝用户时给出选项而非空手退出）。

---

## 环节 1 · 调研定位 → 2-3 风格候选

**目标**：拿到 2-3 个真实风格方向候选，每个带 token 草稿（色/字/距/质感）+ 适用理由。

**动作序列**：

1. 分支 A：refero 搜同品类真实产品（A1 搜竞品 APP、A3 搜桌面应用）→ 拿 DESIGN.md
2. 分支 B：Zine 路由表定位风格族 → 读 style-families.md 对应族详情
3. 记录每个候选的 token 草稿 + 理由（供环节 2 直接消费）
4. 主参考无匹配 → 次参考（Beautiful UI / Aceternity / 21st.dev）→ 兜底（minimal / Uiverse）
5. 候选给 2-3 个，禁多禁少；附一句取舍理由

**产物格式**：

```
候选1: {来源: refero/Linear | 气质: 极简 | token草稿: 色#4F46E5系/Inter/间距4pt | 理由: 同品类标杆}
候选2: {...}
```

**资源调用**（按分支）：

| 分支 | 主 | 次 | 兜底 |
| --- | --- | --- | --- |
| A | refero-design（MCP） | Beautiful UI（A1）/ Aceternity（A2） | minimal.gallery |
| B | Zine 风格库（本地） | orange-line-illustration | web_search |
| C | 不跑本环节 | — | — |

**退化链**：refero-design skill → styles.refero.design 网站 → web_search → 禁止凭空发挥（告知用户无真实参考可查）。

---

## 环节 2 · 定义约束 → 可校验约束集

**目标**：把环节 1 候选转译成 ≤10 条可执行可校验的约束。

**动作序列**：

1. 取 Kami 十条不变量 + design-tokens.css 打底（所有场景常驻）
2. 从选定候选提取：色板（取色验证 R≥G>B 暖调）→ 字体栈 → 间距（4pt 基准）→ 质感规则
3. 分支 A 补交互约束层：导航/状态/反馈（A1 用 design-md-skill 生成 DESIGN.md；或从 Beautiful UI 范式转译）
4. 输出约束集：每条满足"可执行 + 可校验"

**产物格式**：

```
约束集:
1. 底色 #f5f4ed 暖调（禁纯白/冷灰）
2. 唯一彩色 --brand（面积 ≤5%）
3. 字体: serif 400/500 两档（禁加粗/斜体）
...
```

**资源调用**：Kami 骨架（C 规则·主·常驻）→ refero 选定 DESIGN.md（C 直引）→ design-md-skill（C 生成·A1）→ Zine 族配方（C 转译·B）。

**退化链**：Kami 骨架文件 → Kami 轻量版 README（本地）→ 十条不变量心法手动应用。

---

## 环节 3 · 产出 → 实际产物

**目标**：严格按约束集产出，禁止临场发挥。

**动作序列**：按分支调 E 工具（见 SKILL.md 分支 B 表 + registry E 角色）→ 产出 → 对照约束集自查一遍再交付。

**资源调用**（按分支）：

| 分支 | 执行工具 |
| --- | --- |
| A | kami（排版）/ huashu-design（HTML 高保真）/ Figma 家族 / motion（动效） |
| B1 海报 | gpt-image-2（图像）+ kami（排版） |
| B2 杂志 | gpt-image-2（插图）+ kami（版式网格） |
| B3 PPT | guizang-ppt-skill |
| C1 素材 | Lucide / Fonts / Patterns 直引 |
| C2 动效 | motion / motion-dev-animations |
| C3 文档 | kami 技能 |

**退化链**：对应技能 → 手写 HTML/任何绘图工具遵循令牌 → 任何能产出内容的工具。

---

## 环节 4 · 校验 → 达标/回炉

**目标**：对照约束集自检，不达标**回环节 2 改约束**（不打补丁）。

**动作序列**：

1. Kami 三查：取色 R≥G>B / 品牌色面积 ≤5% / 页面密度 60-80%
2. 风格一致性：逐条核对约束集（色板/质感/排版）
3. 分支 A 补 UX QA：导航/状态/反馈可用性（design-qa-checklist）
4. 成品视觉评审（huashu 5 维）
5. 任一不达标 → 明确写"回环节 2：改哪条约束"，不静默打补丁

**产物格式**：

```
校验结果: PASS / FAIL
FAIL 项: {约束3: 品牌色面积超8% | 修正: 回环节2 收紧点缀色规则}
```

**资源调用**：Kami 三查（V 规则·主）/ huashu 5 维（V 规则·主）/ design-qa-checklist（V 规则·A）/ Zine 风格一致性（V 规则·B）。

**退化链**：脚本检查 → 取色器 + 目测 → 三条检查规则人脑执行。
